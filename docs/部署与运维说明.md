# 服务部署与运维（v3.4.0）

这里的命令是操作说明，生成材料不会安装服务或创建定时任务。正式切换、sudo、数据迁移、Hermes 和 Cloudflare 均由部署负责人安排。上线前保存当前版本、完整配置、数据版本和数据库备份。开发使用 8890 与独立数据副本，不能和正式进程同时打开同一个 DuckDB 文件。

## 目录与版本

- `~/cost-studio/releases/<tag>/`：从本地 Git 标签导出的源码，包含版本文件、依赖锁和脚本；没有客户数据、设计稿、协作材料或打包运行时。
- `~/cost-studio/current`：当前 release 的符号链接。
- `~/cost-studio/venv`：目标 Intel Mac 使用 uv 创建的 Python 3.12 x86_64 环境。`requirements-server.txt` 固定 DuckDB 1.5.6 与 python-calamine 0.8.3。
- `~/cost-studio-data/v2`：迁移现有仓库及全部原件；`--data` 指向它的父目录。
- `~/cost-studio-data/logs`：server、watchdog 日志。
- `~/cost-studio-data/backups`：每日数据库备份，保留最近三个日期；不包含原始 Excel，不能代替首次完整迁移备份。
- `~/cost-studio-data/release-backups`：升级前 DB/WAL 备份，不自动清理。
- `~/cost-studio-data/sync_runs.duckdb`：独立同步日志；`sync_latest.json` 为健康接口读取的原子摘要，不会跨进程打开业务库。
- `DATA_ROOT/raw/outbound_detail/YYYY/MM/<业务日>__<taskId>.xlsx`：导出原件。自动导出文件必须位于指定 `--export-root`（默认 `~/zto-exports`）内，不能移动接口返回的任意路径。`DATA_ROOT` 默认 `~/zto-data`，归档成功才删除下载区原件。

## 首次切换顺序

1. 暂停用户写入，读取正式 `/api/identity`、`/api/v2/meta`，保存配置和数据基线。确认端口进程确实属于该数据目录后正常停止旧服务。
2. **停止后**完整复制 `data/v2`（包括 WAL、originals、uploads），逐文件 SHA-256 核对；不要复制仍在写入的 DuckDB。
3. rsync 备份目录到目标机 `~/cost-studio-data/v2/`，再逐文件核对。不要用 `--delete`，不要迁移旧版 SQLite/datasets。
4. 导出已验收的本地 Git 标签到 `releases/<tag>`，创建 venv、安装固定依赖、执行 import/架构自检。首次启动前再次保留迁移前 DB/WAL。
5. 创建 current 链接，按下节生成并安装 LaunchDaemon。首启自动从 raw 重算交件业务日；已有数据版本只增加一次。寄件日期、费用和用户模拟配置不改变。迁移失败事务回滚，服务不接收请求。
6. `/api/health` 核对版本、记录数、生效数、待核数；同时核对 8/9 月寄件基准及完整用户配置。已有库版本 12 首启成为 13，这个增量是日期迁移，并非导入了新记录。
7. 补数、重跑去重验收、杀进程自愈和重启系统验收由部署负责人在正式切换窗口执行。完成后才创建日常任务；旧机正式端口保持停用。

## LaunchDaemon 与看门狗

目标机运行（替换 LAN 地址、域名；生成命令不安装）：

```bash
~/cost-studio/venv/bin/python ~/cost-studio/current/scripts/prepare_232.py \
  --lan 192.0.2.2 --domain cost.example.com --output ~/cost-studio/install
```

脚本输出具体 `sudo install` / `launchctl bootstrap` / Hermes 命令，请审阅后再执行。生成的主服务 `uk.wuxiaoxia88.cost-studio` 使用当前用户、KeepAlive、RunAtLoad、10 秒节流；HTTP 监听 0.0.0.0，仅接受指定四个 Host。默认开发启动仍只监听 127.0.0.1。端口被占用时报错，不悄悄换到随机端口。

看门狗 `uk.wuxiaoxia88.cost-studio.watchdog` 每 60 秒请求 `/api/health`，连续 3 次失败请求 kickstart，重启后冷却 300 秒。主服务崩溃后的快速拉起由 KeepAlive 负责；看门狗处理进程尚存却无响应的情况，不承诺三次探测在 60 秒内完成。

看门狗以 root 运行，只执行 root 所有、不可被普通用户改写的 `/Library/Application Support/CostStudio/watchdog.py`；使用系统 Python 的标准库，不导入应用或用户站点包。应用使用单独 Python 3.12，不能用系统 Python 3.9 替代。安装时 `root:wheel 0644`，目录 0755。

```bash
sudo launchctl print system/uk.wuxiaoxia88.cost-studio
sudo launchctl kickstart -k system/uk.wuxiaoxia88.cost-studio
curl -fsS http://127.0.0.1:8888/api/health
```

外网没有应用内密码；Cloudflare Access 和连接器的 JWT 验证必须先配置好，再开放域名。X-App-Token 防止跨站写请求，不能代替身份认证。局域网按用户选择不加登录，拥有白名单地址访问权限的局域网用户能操作本应用。

## 后续版本发布与回滚

```bash
# 开发机：只创建本地标签，不推送；标签指向已验收提交。
git tag -a v3.4.0 -m 'Release v3.4.0'
COST_DEPLOY_SSH=user@host scripts/deploy_232.sh v3.4.0 --plan
COST_DEPLOY_SSH=user@host scripts/deploy_232.sh v3.4.0
```

第二条只列计划和文件，不连接远端。第三条才实际传输、安装依赖和重启，远端交互式 sudo 由执行人完成。首次安装按上一节执行；该升级脚本要求旧 current 和两个 LaunchDaemon 已存在。release 目录已存在时拒绝覆盖。

升级前比较 requirements-server.txt：内容相同且已有运行时则跳过 uv 同步，仅自检；变更时只使用 --offline，缺缓存就在切换前退出，应提前准备依赖。获取同步互斥锁后，通过服务进程内 CHECKPOINT 生成一致性备份，复制到 release-backups 并核对 SHA-256 与字节数。

默认保持当前 plist：仅原子切换 current，再 kickstart -k 主服务，不卸载/重新注册服务或看门狗。若验收版本需要变更 plist，将已审核的 plist 放在 release/deploy/ 对应标签文件名下；脚本按解析后的内容比较，有变化才 bootout，轮询 launchctl print 确认服务不存在（最多 30 秒），再安装并 bootstrap。权限错误不当成已卸载。

健康检查核对版本与数据目录。失败回滚先卸载并确认停止，再把失败 DB/WAL 保存到备份下 failed-state，恢复备份与旧 current/plist，重启旧服务及看门狗。正常发布不改变看门狗或 Hermes 配置。发布窗口需停止人工导入及编辑；同步互斥只阻止每日任务，不阻止浏览器人工写入。依赖变更应先验证与回滚版本兼容，此版本依赖未变。

手动回滚：停看门狗和主服务 → 完整保留失败库 → 将 release-backups 中匹配的 DB/WAL 恢复（没有 WAL 的备份不能保留新库 WAL）→ current 切回旧 release → 启动主服务及看门狗。不要只回滚代码却使用口径已迁移的数据库。

## 每日同步与对账

在目标机用 venv 执行：

```bash
~/cost-studio/venv/bin/python ~/cost-studio/current/scripts/daily_sync.py run
~/cost-studio/venv/bin/python ~/cost-studio/current/scripts/daily_sync.py run --from 2026-10-11 --to 2026-10-16
~/cost-studio/venv/bin/python ~/cost-studio/current/scripts/daily_sync.py status --days 7
~/cost-studio/venv/bin/python ~/cost-studio/current/scripts/daily_sync.py backup
```

默认同步昨天及前两天，`--recheck-days` 可调整。按 Asia/Shanghai 计算日期。每一天查询窗口 D 12:00:00 至次日 11:59:59，固定 queryDateType=2。日期格式支持原件字符串与 Excel 序号；导入、迁移共用业务日 SQL 函数。无法解析的日期不会猜填。

ZTO-CLI API Key 只从目标机 `~/Library/Application Support/zto-cli/server.json` 的 apiKey 字段在内存读取；不放在命令、日志、任务提示词或源码中。两个 HTTP 客户端仅连接回环地址，不跟随重定向，不使用环境代理。

每个业务日先调用 `outbound-bill/query`，读取严格整数票数 N；再保存北京时间 T0、N、runId 和关联口径，调用 `create-export-task` 一次，使用平台默认文件名且 jobName 留空。平台创建响应可能为 data:null，不能据此确认已建任务。

随后完整分页读取 `fetchTaskApi`。候选必须同时满足：taskName 以 `出港账单(包补收)-业务账单_网点业务账单运单明细_` 开头、createTime 在 **[T0−5秒, T0+120秒]**（含边界）、total **严格等于 N**。total=null 时继续等待，不用已处理条数代替。恰好一条才关联；多条立即失败，零条从T0起等待满5分钟仍无匹配则失败；不选择“最新任务”或放宽票数。status=2 为执行中，只有3成功才下载；已关联任务最多等15分钟完成。分页不完整、记录重复或标识改变都失败报告。时间窗固定，不随重试扩大。

创建请求只提交一次。响应异常或中断后，自动接续查原 T0/N，不重新查新票数或新建任务；已完成的业务日复跑才重新查询及创建。负责人核实旧任务不再使用后，可显式指定 `--restart-export YYYY-MM-DD`（可重复传入多个日期，不能与同日 `--resume` 混用）；旧日志保留，新记录写 supersedes，原导入仍待核对时拒绝重建。自动任务绝不启用该参数。v3.4.0 客户端通过 version_ok 接受版本 ≥3.2.1 的服务，支持发布前在独立源码目录验证。

多个业务日严格串行：上一天下载、校验及入库完成才创建下一天；任一天失败则停止后续日期创建，并报告跳过的日期。整次运行继续使用互斥锁。

ZTO-CLI 覆盖适配器 `outbound-bill-export.yaml` 的 createJob.staticPayload.fileName 保持固定 `出港账单(包补收)-业务账单`，不提供自定义 fileName。jobName 参数可以保留为字符串、internal、默认空串；同步不传该参数。修改覆盖文件前先备份并热加载，其他适配器保持原状；应用发布归档不包含目标机私有配置。

已按时间和票数确认 taskId 后首次下载；文件不完整、为错误图片或取链接失败时，使用**同一 taskId** 调用 `outbound-bill-export/fetch-download-link` 获取新签名链接。每隔 60 秒重下一次，最多额外 5 次；先写下载目录临时文件，ZIP/XLSX 校验成功后原子替换，再做表头、票数和金额对账。下载请求仅访问指定 HTTPS 文件服务、不携带 API Key、不跟随跳转；签名 URL 不记日志。重试次数落盘，自动接续不会重置五次预算。五次仍失败才标“结果未确认”，输出 taskId 并以失败退出，交由后续配置的 Hermes local 投递报告（未创建任务时以终端和同步状态报告）；全程不新建导出任务。

人工核对原任务后可使用 `--resume` 接续已有文件；显式接续会重置该任务的下载重试预算：

```bash
~/cost-studio/venv/bin/python ~/cost-studio/current/scripts/daily_sync.py run \
  --from YYYY-MM-DD --to YYYY-MM-DD --resume YYYY-MM-DD TASK_ID /完整路径/已下载原件.xlsx
```

进程中断后，已知文件的日期会自动接续；已持久化 T0/N 的任务自动按原条件查询，旧版缺少该关联证据的未知任务需人工核对后使用上面命令。单机文件锁防止定时与手动同步重叠。日志保留每次运行、每个日期的状态、任务编号、原件路径、表头新增/缺失、票数、金额差额及导入统计。

创建前票数 N、任务 total、下载行数、唯一运单数、下载后重新查询的 billCount 必须相等，且交件时间全部在该业务日内，否则不导入。总费用差额仅记录（单位元，采用源账单原值，不推定含税/不含税）；未知列原样保留，必需列缺失才失败。导入组有日期范围名称，独立指定 replace，不改变用户手动导入的冲突设置。重复原件/重复行不增加数据版本；最新变化票替换旧票并留撤销记录。

新补录件可能有较早的寄件日期。因此“迁移不改变寄件基准”应在补数前验证；补数新增历史寄件必须如实计入，并报告新增量，不能为了维持旧基准而排除。

Hermes 每日 14:00 同步、03:00 备份，均 no_agent、投递 local。生成器提供创建命令；创建前 `cron list` 防重名，并确认 Hermes 有效时区为 Asia/Shanghai（环境 HERMES_TIMEZONE、配置 timezone、系统时区依次生效）。任务包装器放 `~/.hermes/scripts/`，显式调用应用 venv，不能依赖 Hermes 默认 Python。

## 备份和排障

每日备份通过 HTTP `POST /api/v2/backup` 携带 bootstrap 返回的 X-App-Token。服务写锁内 CHECKPOINT、完整复制、fsync、原子替换；成功后保留 3 份。只读查询不阻塞为写进程；不得从另外的 Python 进程打开正在运行的 warehouse.duckdb。恢复备份必须先停止服务。

- 健康接口不可达：检查端口、Host 白名单、launchctl print、logs/server.err.log；不要绕过 Host 校验。
- 出现锁错误：查是否有遗留开发进程打开正式库；不要删除 WAL 或强制并发打开。
- 同步失败：`status --days 7` 查具体日期；票数差异先检查原平台导出是否完整及账单是否后补，不能直接跳过对账。
- 备份失败：检查空间和 CHECKPOINT 返回；原来的有效备份不会被失败文件覆盖。
- Hermes 静默：local 投递保存在本地，不代表发给外部联系人；核对任务状态和最近运行日志。
- 不在外网访问原始服务 9800；已有 ZTO Tunnel / Access 规则保持原状。


### v3.4 预热和资源

启动后后台线程预计算上月、本月、本次导入的网点分析与元数据；数据/配置版本或导入批次状态变化后重建。冷启动请求等待同一项计算，不会重复扫描。API 仍为 no-store，进程内 LRU 保存不可变 JSON 与 gzip；导出快照与页面版本一致。首屏仅传前 30 名和分群摘要，展开由 `/api/v2/analysis/details` 按 snapshotId 读取。

`GET /api/v2/analysis/default` 是只读上月首屏；`GET /api/v2/revision` 用于已打开页面更新检查。HTML 不长期缓存；`v34.bundle.js?v=3.4.0` 与 CSS 可长期缓存。修改 JS 后须运行 `python scripts/build_web.py`。保留 v3.3.1 的 backlog=128 与同步版本兼容修复。

港澳台显示配置只作用于新的测算，不删除运单。旧分组首次读取时自动补入未归组的香港/澳门/台湾，默认 showHMT=false，用户既有模拟数值与开关保留。
